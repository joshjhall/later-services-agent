# AGENTS.md

Context for AI coding agents working in this repo. `CLAUDE.md` is a symlink to this file.

## What this is

A take-home exercise for a VP, UX role at Later (brief: `reference/Later___VP__UX_Take-Home_Exercise.pdf`). Later's Services team runs fully managed influencer campaigns for enterprise brands. The task: design the day-to-day experience of a Services **campaign manager** working with an **agent** that takes on repetitive coordination work while the human stays accountable.

Deliverables:

1. **Brief** (1–2 pages or ≤5 slides): problem framing, trust and control principles, what was cut and why, what to test next, which patterns to standardize across a multi-agent product.
2. **Working prototype** covering: stating the goal, reviewing the agent's proposed creator lineup, and one hard moment (agent unsure, agent wrong, or creator goes quiet near a deadline).
3. **Supporting artifacts**: assumptions, workflow diagrams, problem statements, and other inputs to the prototype.

Timebox: 2–4 hours. Presented in a 60-minute panel: a 20-minute walkthrough, discussion, then **a small live change** to the prototype. Keep the code easy to change live.

## Stack

- `app/`: Vite, React 19, TypeScript 7, Tailwind v4, shadcn/ui (radix-nova preset; `cn` from the `cn` package). Path alias `@/` → `app/src/`.
- LLM behaviour is **faked or kept to simple patterns** for the demo (scripted or deterministic agent responses). A production build would use an agent orchestration stack such as LangGraph; that is a deliberate cut to avoid a Python service in the timebox.
- `docs/`: assumptions, flows (Mermaid), the brief, and the rendered `overview.html`.
- `design-system/`: agent-readable design system (stub). See `docs/design-system-proposal.md`.
- `app/src/agent/rules.ts`: the simulated agent. Tunables are in `AGENT_POLICY`.
- `containers/`: devcontainer build tooling (git submodule, `update = none`). Not project content.

## Commands

`just` lists recipes. The main ones are `just dev` (<http://localhost:5173>), `just test`, `just build`, `just lint`, `just fmt`, and `just ui <component...>` to add shadcn components.

## Working agreements

- **Before building UI, read `design-system/README.md`**, then only the component and pattern files you need. Use documented components; if none fit, fill in `design-system/04-component/_request-template.md` and stop for review.
- `app/src/components/ui/` is generated by `shadcn add`: biome formats it but does not lint it. Prefer composing over editing it.
- `reference/` holds material received from Later. Keep it verbatim.
- Write assumptions down in `docs/assumptions.md` as you make them. The brief asks for them explicitly.
- Use only public information about Later; invent everything else and label it as invented.
- Conventional commits (enforced by conform).
